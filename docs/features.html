deckox-server

公開Web API

Endpoint状態レスポンス
GET/healthz実装済み稼働状態とServerプロセス識別子。再起動後の復帰判定に使用
POST/api/v1/auth/login実装済み単一管理者のログイン。TOTP未設定ならセッションCookieを発行し、設定済みなら短期のdeckox_preauth Cookieとtotp_requiredを返す
POST/api/v1/auth/login/totp実装済みdeckox_preauth Cookieを検証し、TOTPコードまたはリカバリーコードでセッションCookieを発行。リカバリーコードは使い捨て
GET/api/v1/auth/session実装済み現在の認証状態
POST/api/v1/auth/logout実装済みセッションを無効化
GET/api/v1/status実装済みServerの名前・バージョン・状態・待受ポート・Webhook設定有無とAgent状態。Agent障害時はdegraded
GET/api/v1/events?after=実装済みServerのイベントフィード。Agentが報告したイベント(サービス・ソフトウェア操作、許可リストの変更、再起動・更新、スケジュール実行)と、Server自身が気づいたイベント(Agentの接続・切断・再起動、プロトコル版の不一致)を、連番で返す。afterに前回のnext_afterを渡して差分を取得
GET/api/v1/jobs実装済みバックグラウンドで実行中・完了したジョブの一覧(新しい順、直近100件)を中継
GET/api/v1/jobs/{id}実装済みジョブ1件の状態(待機中・実行中・成功・失敗)、開始・終了時刻、結果メッセージを中継
GET/api/v1/modules実装済みAgentのモジュール一覧(system・power・update・storage・diagnostics・backups・services・schedules・software)と、Server自身のモジュール一覧(server_modules: audit・realtime・notifications・update-check)、各モジュールが有効か、Agentの接続状態を返す。Serverのモジュールは環境変数DECKOX_DISABLED_MODULESで無効にでき、無効な経路は404 module_disabled(認証後にだけ判定するため、未ログインには設定が漏れない)
GET/api/v1/diagnostics実装済み生成時刻、Server、Agent、ホスト、Deckoxのsystemdユニット、機能設定の安全な固定項目をJSONで返却。Agent不通時も部分診断を返す
GET/api/v1/diagnostics/report実装済み同じ固定スキーマをdeckox-diagnostics.jsonとしてダウンロード
GET/api/v1/update実装済み現在版とGitHubの最新安定版を比較。取得失敗時も外部エラーを隠したunavailableを返す
GET/api/v1/system実装済みAgentのシステム情報APIを中継
GET/api/v1/system/capabilities実装済みホスト再起動・管理画面からの更新がそれぞれAgent設定で許可されているか取得
POST/api/v1/system/reboot実装済み管理者パスワードを再確認し、許可済みのホスト再起動をAgentへ要求
POST/api/v1/system/update実装済み管理者パスワードを再確認し、更新確認済みのバージョン向けinstall.shを取得して、許可済みならAgentへ実行を要求
GET/api/v1/system/metrics実装済みCPU・メモリ・Swap・負荷平均、ネットワーク送受信速度、ディスクI/O速度、任意のCPU温度を中継
SSE/api/v1/events/metrics?interval=1|2|5実装済み拡張リソースメトリクスを認証済みブラウザへ配信。購読者0件では追加統計を含む採取を休止
GET/api/v1/storage実装済みAgentのストレージAPIを中継。既知のシステムマウントポイントには標準タグを付与
GET/api/v1/storage/disks実装済みディスクごとのパーティション・LVM等の構成と、マウント済みのものの使用量を中継(未マウントも含む)
GET/api/v1/backups実装済みAgentのバックアップAPIを中継
GET/api/v1/services実装済みsystemdサービス一覧を中継。各サービスに標準システム・Deckox管理・既知の主要ソフトウェア(Docker・nginxなど)のタグ判定を付与
GET/api/v1/services/{id}実装済みsystemdサービス詳細を中継
POST/api/v1/services/{id}/{action}実装済み起動・停止・再起動・有効化・無効化。Agentの許可・エラー状態を維持して返却
GET/api/v1/services/{id}/logs実装済みlinesとpriority=all|error|warning|infoを検証し、完全一致許可リスト内のjournalログを中継。最大500行
GET/api/v1/services/{id}/logs/report実装済み同じ条件で取得したログをdeckox-service-logs-{id}.jsonとしてダウンロード
GET/api/v1/software実装済み管理対象(許可リスト+自動検出)のパッケージの状態を中継。自動検出されたものにはauto、親にまとめられた子にはparentを付与
GET/api/v1/software/installed実装済みホストにインストール済みの全パッケージ(名前・バージョン・管理中かどうか)を読み取り専用で中継
POST/api/v1/software/{id}/install実装済み管理者パスワードを再確認し(Serverに加えてAgentも検証)、許可済みパッケージをインストール
POST/api/v1/software/{id}/remove実装済み管理者パスワードを再確認し、許可済みパッケージを削除(purgeはしない)
POST/api/v1/software/{id}/upgrade実装済み管理者パスワードを再確認し、インストール済みの許可済みパッケージを最新版へ更新
POST/api/v1/software/{id}/allow実装済みパッケージ名を、ホストに設定済みのリポジトリまたはインストール済みパッケージの中で実在確認したうえで/etc/deckox/agent.tomlの管理許可リストへ追加
POST/api/v1/software/{id}/disallow実装済み管理許可リストから削除
GET/api/v1/schedules実装済みAgentのスケジュール一覧を中継
POST/api/v1/schedules実装済み許可リスト内サービスの起動・停止・再起動を曜日・時刻指定で登録。監査ログに記録
DELETE/api/v1/schedules/{id}実装済みスケジュールを削除。監査ログに記録
POST/api/v1/schedules/{id}/enable実装済みスケジュールを有効化。監査ログに記録
POST/api/v1/schedules/{id}/disable実装済みスケジュールを無効化。監査ログに記録
POST/api/v1/settings/password実装済み現在のパスワードを確認し、Argon2idハッシュを更新して全セッションを失効。5分間に5回の確認失敗で制限
GET/api/v1/settings/totp/status実装済みTOTP有効状態と残りリカバリーコード数
POST/api/v1/settings/totp/setup実装済みBase32シークレットとotpauth URIを発行。この時点ではアカウントへ保存しない
POST/api/v1/settings/totp/confirm実装済みコード検証後にTOTPを有効化し、リカバリーコード10個を一度だけ平文で返す
POST/api/v1/settings/totp/disable実装済み現在のパスワードとTOTP・リカバリーコードを確認してTOTPを無効化
POST/api/v1/settings/webhook/test実装済みDECKOX_WEBHOOK_URLへテスト通知を送信し、結果を監査ログに記録。未設定時はwebhook_not_configuredを返却
GET/api/v1/audit?limit=&before_ms=実装済み認証・パスワード変更・TOTP設定・サービス操作・ホスト再起動・CLI操作の監査ログを新しい順にページング取得
GET/api/v1/audit/report実装済み保存されている監査ログ全件をdeckox-audit.jsonとしてダウンロード
GET/*実装済みVue静的ファイル。未知のパスはindex.htmlへSPAフォールバック

deckox-agent

内部Agent API

Endpoint状態取得内容
GET/v1/health実装済みAgentプロセスのヘルス状態
GET/v1/info実装済みAgentのプロトコルバージョンとAgentの版、プロセスごとの識別子(epoch)。ServerとAgentの版がずれていないかの確認に使う
GET/v1/events?after=&epoch=実装済みAgentが記録した直近500件のイベントを、連番で返す。Agentが再起動するとepochが変わり、連番は1から始まり直す。AgentからServerへは接続せず、Serverが取りに来る
GET/v1/jobs, /v1/jobs/{id}実装済み?async=true付きで開始した操作のジョブ。ソフトウェア操作・サービス操作は?async=trueを付けると、待たずに202とジョブを返し、結果はジョブとイベントで確認できる。付けない場合は従来どおり結果を待って返す。同じ資源への操作(パッケージ、ホスト、サービス単位)は重ならず順番に実行される
GET/v1/modules実装済みモジュールごとの有効・無効、依存するモジュール、担当する経路の前置き。agent.tomlの[modules] disabledに書いたモジュールは無効で、その経路は404 module_disabledを返し、そのモジュールだけが使う常駐処理(スケジューラなど)も起動しない。書き間違いや、依存先を無効にした設定は、Agentが起動時に理由つきで拒否する
GET/v1/status実装済みホスト名、OS、CPUアーキテクチャ、/proc/uptimeの秒数
GET/v1/diagnostics実装済みAgentバージョン、安全なホスト情報、Deckoxの2ユニット状態、再起動・更新の許可状態と許可サービス数を固定スキーマで返却
GET/v1/system実装済みOS、バージョン、カーネル、ホスト名、稼働時間、boot ID、タイムゾーン、物理ネットワークインターフェースのLAN IPv4アドレス
GET/v1/system/capabilities実装済み設定に基づくホスト再起動・更新実行の許可状態
POST/v1/system/reboot実装済み許可時のみsystemctl --no-block rebootを実行
POST/v1/system/update実装済み許可時のみ、Serverが取得したタグ固定のinstall.shを検証して/run/deckox/update.shへ書き込み、systemd-runで独立ユニットとして実行
GET/v1/system/metrics実装済みCPU使用率・コア数・任意の温度、メモリ・Swap、ロードアベレージ、ネットワーク送受信速度、ディスク読み書き速度。追加統計が取得不能でも他の値を返却
GET/v1/storage実装済みファイルシステム、形式、マウントポイント、容量・使用量、既知のシステムマウントポイント判定。squashfs(snapなど)・devtmpfs・efivarfsは除外。画面の全体使用率は、tmpfsやoverlayを除き、同じデバイスの複数マウントを1回だけ数える
GET/v1/storage/disks実装済みlsblkのJSONから物理ディスクとその上のパーティション・LVM・暗号化デバイスを読み取り、dfの使用量と結合。lsblkが使えないホストでは空配列
GET/v1/backups実装済み/var/lib/deckox/backups/配下のバックアップ一覧(名前・更新前バージョン・取得日時・サイズ)。root:root所有のためAgent経由でのみ読み取り可能
GET/v1/services実装済みlist-unitsのロード済みサービスに、list-unit-filesにあるが未ロードのサービス(未起動・無効のもの)を加えた一覧。他のユニットが名前だけ参照しているLoadState=not-foundのユニットは、許可リストにあるもの以外は除外。有効化状態と既知の主要ソフトウェア判定を付与
GET/v1/services/{id}実装済みサービス詳細、Main PID、操作許可状態
POST/v1/services/{id}/start実装済み許可リスト内のサービスを起動
POST/v1/services/{id}/stop実装済み許可リスト内のサービスを停止
POST/v1/services/{id}/restart実装済み許可リスト内のサービスを再起動
POST/v1/services/{id}/enable実装済み許可リスト内のサービスを有効化
POST/v1/services/{id}/disable実装済み許可リスト内のサービスを無効化
GET/v1/services/{id}/logs実装済み許可リスト内のサービスに限定してjournalを取得。最大500行、all|error|warning|infoのpriority絞込に対応
POST/v1/services/{id}/allow実装済みサービスの存在を確認したうえで/etc/deckox/agent.tomlの許可リストへ追加。Deckox自身の2ユニットは対象外
POST/v1/services/{id}/disallow実装済み/etc/deckox/agent.tomlの許可リストから削除。Deckox自身の2ユニットは対象外
GET/v1/software実装済み管理対象パッケージについて、ホストのパッケージマネージャー(apt/dnf/pacman/zypper)からインストール状態・バージョンを読み取り。インデックスの更新は行わない。auto_adopt(既定で有効)のとき、自分でインストールしたパッケージを自動で管理対象に含める(apt: apt-mark showmanualの結果。他の手動インストール済みパッケージから依存・推奨されているもの(docker-ce-cliなど)は、その親(docker-ce)の子として束ね、画面で展開して表示。dnf: --userinstalledの結果を、rpm -qaのRequires/RecommendsとProvidesで突き合わせて同様に束ねる。pacman: -Qqet(他から必要とされない明示インストール)。zypperは非対応)。必須・重要・Essentialのパッケージは対象外
GET/v1/software/installed実装済みパッケージマネージャーのローカルDB(dpkg-query / rpm -qa / pacman -Q)からインストール済みの全パッケージを読み取り。許可リストとは無関係で、操作の権限は与えない
POST/v1/software/{id}/install実装済み許可済みなら、インデックス更新後にパッケージをインストール
POST/v1/software/{id}/remove実装済み許可済みならパッケージを削除(設定・データは残す)
POST/v1/software/{id}/upgrade実装済み許可済み・インストール済みの場合だけ、インデックス更新後に最新版へ更新
POST/v1/software/{id}/allow実装済みホストに設定済みのリポジトリ、またはインストール済みパッケージの中でパッケージ名を実在確認したうえで/etc/deckox/agent.tomlの[software]許可リストへ追加。第三者リポジトリは追加しない
POST/v1/software/{id}/disallow実装済み[software]許可リストから削除。自動検出されるパッケージはdismissedに記録し、以後は自動追加しない
GET/v1/schedules実装済み登録済みスケジュールの一覧(サービス・操作・曜日・時刻・有効状態・前回実行結果)
POST/v1/schedules実装済み許可リスト内のサービスのみ登録可能。曜日(月-日)・時刻(ホストのローカル時刻)・起動/停止/再起動を指定。/var/lib/deckox/schedules.jsonへ永続化
DELETE/v1/schedules/{id}実装済みスケジュールを削除
POST/v1/schedules/{id}/enable実装済みスケジュールを有効化
POST/v1/schedules/{id}/disable実装済みスケジュールを無効化(削除せず一時停止)
Agent APIはTCPではなく、/run/deckox/agent.sock上で提供されます。

Vue web

管理画面

実装済み

リアルタイム概要

OS・カーネル・稼働時間と、CPU・メモリ・Swap・ロードアベレージ、ネットワーク送受信速度、ディスクI/O速度の現在値・最大120点のSVG推移グラフ、最終更新時刻を表示します。CPU温度は取得可能な場合だけ表示し、Swap使用率80%以上を警告します。マウントのうち最も使用率が高いものをディスク使用率として表示し、90%以上で警告します。物理ネットワークインターフェースのLAN IPv4アドレスとServerの待受ポートから組み立てたアクセスURLをコピーボタン付きで表示します。Agent復旧時はシステム情報を自動取得します。

実装済み

管理者ログイン

セッション確認、ログイン、ログアウト、TOTP設定時の2段階目コード入力、APIの401応答時のログイン画面復帰、パスワードを忘れた場合のSSHコンソール手順案内を提供します。

実装済み

二要素認証(TOTP)

設定画面でBase32シークレットとotpauth URIを表示して有効化し、確認コード入力後にリカバリーコード10個を一度だけ表示します。残りコード数の確認と、パスワード・コード確認付きの無効化を提供します。

実装済み

監査ログ

認証・パスワード変更・TOTP設定・サービス操作・ホスト再起動・SSHコンソールからのCLI操作を時刻・種別・actor・送信元IP・結果で一覧表示し、イベント種別・結果で絞り込み、JSONとして保存できます。

実装済み

サービス管理

systemd一覧・検索・状態表示と、許可された起動・停止・再起動・有効化・無効化を提供します。許可対象のjournalログは最大500行まで表示し、全件・エラー・警告・情報で絞り込め、表示中の内容をJSONファイルとして保存できます。許可リストへの追加・削除もこの画面から行え、追加時はサービスの実在確認、削除時は確認ダイアログを挟みます(SSHでの/etc/deckox/agent.toml手動編集は不要になりました)。Deckox自身の2ユニットは許可リストの対象外です。各サービスには「標準」(OS・パッケージ提供のユニット)・「Deckox」(自身が管理するユニット)に加えて、ユニット名から判定したDocker・nginx・PostgreSQLなど既知の主要ソフトウェアのタグを表示します。表示するタグの一覧はホスト上で実際に見つかったタグから組み立てられ、タグ単位での表示・非表示切り替え、検索語としての一致に対応します。非表示にしたタグはブラウザに保存され、次回このブラウザで画面を開いたときも同じ表示状態になります。

実装済み

サービスのスケジュール実行

許可リスト内のサービスに限り、起動・停止・再起動を曜日と時刻を指定して自動実行できます。Agentがホストのローカル時刻で20秒ごとに確認し、該当する時刻・曜日で一度だけ実行します(継続的な再実行はしません)。一覧では前回の実行日時と成否を確認でき、削除せず一時的に無効化することもできます。Deckox自身の2ユニットはスケジュール対象外です。

実装済み

ソフトウェア管理

固定カタログは持たず、管理者が入力したパッケージ名を、そのホストに設定済みのリポジトリだけを対象に実在確認してから管理許可リストへ追加します(第三者リポジトリ・GPG鍵の追加は行いません)。許可リスト内パッケージのインストール状態・バージョン・入手可能なバージョンを表示し、インストール・削除・最新版への更新ができます。実行には管理者パスワードの再確認が必要です。apt(Debian・Ubuntuなど)・dnf(Fedora・RHEL系)・pacman(Arch Linuxなど)・zypper(openSUSEなど)に対応し、ホストのパッケージマネージャーを起動時に自動判定します。pacmanホストではインストール・更新のたびにホスト全体のパッケージも同時に最新化されます(依存関係の不整合を避けるための挙動)。Alpine Linux(OpenRC)には未対応です。

実装済み

ストレージ

マウントポイントごとの容量・使用率・空き容量を表示し、全マウント合計の使用率とマウント別の使用配分を色分けした内訳で示します。/や/homeなど既知のシステムマウントポイントには「標準」タグを表示し、サービス画面と同じ表示・非表示切り替えに対応します。

実装済み

ホスト再起動

Agent側で明示的に許可した場合だけ、管理者パスワードを再確認して再起動し、新しいServerプロセスを検知してログインへ戻ります。

実装済み

Agent障害表示

接続エラーやLinux専用APIのエラーを各画面へ表示します。

実装済み

Webhook通知

DECKOX_WEBHOOK_URLを設定すると、管理画面を開いていなくてもServerが30秒間隔で許可済みサービスのfailed状態・Swap使用率80%以上・最も使用率が高いマウントの90%以上・Agentへの接続断・新しいDeckoxバージョンの公開を監視し、状態が変化した瞬間だけJSONをPOSTします。継続中の状態を繰り返し通知することはありません(新バージョン公開はキャッシュ済みの更新確認結果を使うため、GitHubへの追加アクセスは発生しません)。設定画面からテスト通知を送信でき、送信結果は監査ログにも記録されます。

実装済み

システム診断

Server・Agentの状態、公開可能なホスト情報、Deckoxユニット状態、権限設定の要約に加えて、aptの既存キャッシュから読む更新可能パッケージ数を専用画面に表示し、同じ内容をJSONで保存します。パッケージ数の取得はapt updateを実行しないため、キャッシュが古いままの場合があります。同じ画面で、インストーラーが更新前に/var/lib/deckox/backups/へ保存したバックアップの一覧(取得日時・更新前バージョン・サイズ)も確認できます。Agent不通時もServer側の結果を表示します。

更新確認と更新実行

設定画面で現在版と最新安定版を確認し、検証済みのタグに限ってReleaseリンクとコピー可能な更新コマンドを表示します。Agent設定で許可した場合だけ、確認済みの更新がある間「今すぐ更新」ボタンが表示され、管理者パスワードの再確認後にServerが取得したインストーラーをAgentが独立したsystemdユニットとして実行します。許可していない環境では引き続き手動確認・手動実行のみです。

deckox-protocol

共有Protocol型

ServerとAgentが共有するSerialize/Deserialize可能なRust型です。

型状態内容
HealthResponse使用中Agentのヘルス応答
AgentStatus使用中AgentからServerへ返すホスト状態
SystemInfoほか使用中システム、CPU・メモリ・Swap・ネットワーク・ディスクI/O・任意温度のメトリクス、ストレージ、サービスとjournalログの応答型
SystemCapabilities使用中Agent設定に基づくホスト再起動の許可状態
UpdateStatus使用中現在版、最新版、確認日時とup_to_date・available・unavailable状態
RealtimeMetricsEvent使用中SSEの連番、取得時刻、Agent接続状態、拡張メトリクス、エラーコード。取得不能な追加値は省略可能
DiagnosticsReportほか使用中生成時刻、Server・Agent状態、boot IDを除いたホスト情報、Deckoxユニット状態、再起動許可・許可サービス数
ServiceAction使用中systemdサービスの起動、停止、再起動、有効化、無効化
ScheduleAction使用中ServiceActionのうちスケジュール可能な起動・停止・再起動のみの部分集合
ServiceSchedule / CreateScheduleRequest使用中スケジュールの登録内容(サービス・操作・曜日・時刻)と、Agent側の状態(有効/無効・前回実行日時・結果)
SoftwarePackage使用中管理許可リスト内パッケージの状態(名前・インストール状態・バージョン・入手可能バージョン・更新有無)
SoftwareAction使用中パッケージのインストール、削除、更新
CommandResult使用中操作完了時のコマンドID、実行状態、メッセージ
AgentCommand型のみ定義済み汎用コマンド型。現在のHTTPハンドラーでは未使用
AuditEvent / AuditPage使用中監査ログの1件と、新しい順のページング応答。Server専用でAgent側の型は変更していない
診断データの境界: 診断は固定した安全な項目だけを構築します。生の設定ファイル、環境変数、ログ、パスワード、パスワードハッシュ、セッション、Cookie、boot IDはAPI・画面・ダウンロードへ含めません。
サービス管理の境界: 専用HTTPエンドポイントとServiceActionで実装されています。ログ閲覧も完全一致許可リスト、最大500行、all|error|warning|infoだけを受け付けます。許可リストの追加・削除は/etc/deckox/agent.tomlへの直接書き込みのみで行い、サービス自体の起動・停止などとは独立した専用エンドポイントです。汎用AgentCommandとWebコンソールは使っていません。
ソフトウェア管理の境界: 固定のソフトウェアカタログは持ちません。管理許可リストへ追加できるのは、そのホストに既に設定済みのパッケージリポジトリで実在確認できたパッケージ名か、すでにインストール済みのパッケージだけです。インストール済みパッケージの一覧は読み取り専用で表示でき、そこから選んで追加できます。またauto_adopt(既定で有効)のとき、自分でインストールしたパッケージは自動で管理対象になります。Deckoxが新しいリポジトリやGPG鍵を追加することはありません。[software]許可リストは[services]と同じ思想の別テーブルで、書き込み時にどちらのテーブルも互いを破壊しないよう境界を区切って置換します。

未実装

複数ユーザー・ロール

アカウントファイルはユーザー名をキーにした構造ですが、実際に扱うのはadmin単一アカウントだけです。複数ユーザーの作成・ロール分けはありません。

未実装

専用のLinux管理画面

ファイル・ネットワークを型付き操作で管理する専用API・画面はありません。パッケージ管理は実装済みですが(「ソフトウェア管理」を参照)、Deckoxからインストールしたソフトウェア自体の設定・操作(例: nginxの設定編集、Dockerコンテナの管理)はまだできません。Alpine Linux(OpenRC)のパッケージ管理にも未対応です。

未実装

データベース

アカウント・監査ログともにJSON/JSON Linesファイルで永続化しており、外部データベースは使用しません。

未実装

TLS終端

Server自身によるHTTPS提供はありません。
