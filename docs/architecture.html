Architecture

権限と責務を分ける、3つの構成要素。

ソースコードはVue、Axum Server、Rust Agentの3コンポーネントです。実行時はServerとAgentの2プロセスが常駐し、VueはServerが配信する静的ファイルとしてブラウザで動きます。

実行時アーキテクチャ

ブラウザからの操作と通常取得はREST、閲覧中のメトリクス配信はSSEを使います。ServerとAgentはローカルUnixソケット上のHTTPで通信し、Agentは外部TCPポートを持ちません。

コンポーネントの責務

WEB

Vue + TypeScript

ブラウザ上の管理UIです。Vue Routerで画面URLを分け、SSEメトリクス、SVGグラフ、日本語・英語、端末内に保存する表示設定を提供します。

SERVER

Axum Server

Vueの静的配信、管理者認証、公開HTTP API、Agent APIの中継、SSE配信を担当します。一般ユーザーのdeckoxで動作します。

AGENT

Rust Agent

Linuxホスト情報の取得、許可リスト内のsystemdサービス操作、指定ユーザーのSSH公開鍵管理、明示的に許可したホスト再起動を行います。rootで動き、Serverとは権限境界を分けています。

リアルタイムメトリクス

Browser–Server
GET /api/v1/events/metricsのServer-Sent Events。操作APIは従来どおりREST
Sampling
接続中クライアントの最短間隔でAgentから1回取得し、結果を購読者へ共有
Idle
購読者が0件ならAgentへのメトリクス要求を停止
Lifecycle
概要画面以外、非表示タブ、リアルタイム更新を無効にしたブラウザではSSE接続を閉じる
Recovery
切断時は最大30秒の指数バックオフで再接続し、15秒ごとにkeep-aliveを送信

Server–Agent通信

Transport
HTTP over Unix domain socket
Socket
/run/deckox/agent.sock
Permission
0660。systemdではdeckoxグループを使用
Timeout
接続は2秒、レスポンス読み取りは35秒。Agent内のsystemd操作は30秒で打ち切る
Failure
Agentへ接続できない場合、Server状態APIはdegradedとエラー内容を返す

Linux上の配置

/usr/local/bin/deckox-server
/usr/local/bin/deckox-agent
/usr/local/share/deckox/web/
/etc/deckox/
├── server.toml
└── agent.toml
/var/lib/deckox/
└── admin-password.hash
/run/deckox/agent.sock
/etc/systemd/system/
├── deckox-server.service
└── deckox-agent.service

Agentはagent.tomlを読み込み、ソケットの場所を環境変数で上書きできます。Serverは現在、環境変数から設定を読み込み、server.tomlは将来の設定場所として予約されています。

現在のセキュリティ境界

境界実装内容
プロセス分離Web Serverとroot Agentを別プロセス・別systemdユニットに分離
Agent公開範囲Unixソケットのみ。ネットワークポートは使用しない
Server権限専用deckoxユーザー、NoNewPrivileges、ProtectSystem=strict
管理者認証Argon2idハッシュ、HttpOnly・SameSite=Strict Cookie、12時間のメモリ内セッション、ログイン・パスワード再確認の試行制限
変更API認証に加え、ブラウザのOriginとHostが同一であることを確認
Agent操作systemd変更は完全一致許可リスト、再起動は明示的な設定とWeb側のパスワード再確認、SSH鍵管理は指定した非rootユーザーに限定
任意コマンドWebコンソールを提供せず、Agentは許可済みの型付き操作だけを受け付ける
SSH鍵公開鍵だけを受け付け、鍵種別・Base64データ・内部鍵種別を検証。ディレクトリFDとO_NOFOLLOWを用いてリンク差し替えを回避
操作ログ認証、パスワード変更、サービス・SSH鍵・再起動を送信元IP・リクエストID付きでjournalへ記録
未実装: 複数ユーザー・ロール・MFA・TLS終端・監査ログの専用閲覧画面はまだ存在しません。
