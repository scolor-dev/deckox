Design system

画面の見た目を、部品とトークンで揃える。

Web UIの色・間隔・部品はapps/web/src/design-system/に集約されています。ライト/ダークの両テーマに対応し、キーボード操作とコントラストはテストで固定しています。

構成

apps/web/src/design-system/
├── tokens.css          # 色・間隔・角丸・文字・影・動き・z-indexのトークン
├── theme.ts            # テーマ(自動/ライト/ダーク)の解決と適用
├── breakpoints.ts      # CSS変数にできないブレークポイント
├── components/
│   ├── index.ts        # 全コンポーネントのバレル
│   └── AppButton/      # コンポーネントごとのフォルダ
│       ├── AppButton.vue
│       └── AppButton.md   # AI向けの使い方(英語)
├── composables/        # フォーカストラップ、Escapeで閉じる処理
├── catalog/            # 開発用カタログ(本番ビルドに含めない)
└── README.md           # 「どの部品を使うか」の早見表

トークンとテーマ

tokens.cssは三層で定義します。素の:rootがライト、prefers-color-scheme: darkのブロックがOS追従のダーク(明示的にライトを選んだ場合は除外)、:root[data-theme="dark"]が明示的なダークです。data-themeは<html>に付き、設定画面の「テーマ」(自動/ライト/ダーク)と初期描画前のインラインスクリプトが制御します。

色以外(角丸・z-index・間隔・文字サイズ・影・動き)はテーマに依存せず、値を共有します。間隔と文字サイズはスケールの段階値で、直値は書きません。

ルール: Vue/CSSに色・間隔・角丸などの直値を書かず、必ずトークンを使います。新しい色トークンはライト・自動ダーク・明示ダークの3か所に定義します。

アクセシビリティ

  • フォーカス: ダイアログはフォーカストラップを持ち、開くとダイアログ(またはdata-autofocusの要素)へ移動、閉じると元の要素へ戻ります。操作可能な部品はグローバルCSSに頼らず自前の:focus-visibleを持ちます。
  • キーボード: タブは矢印・Home・Endで移動(roving tabindex)、メニューは矢印で項目を移動しEscapeで閉じてトリガーへ戻ります。
  • コントラスト: 文字・バッジ・ボタンの配色はライト/ダークとも WCAG AA(本文4.5:1、補助テキスト3:1)を満たすことをテストで検査します。
  • 動き: アニメーションを持つ部品はprefers-reduced-motionに対応します。
  • 自動検査: axe-coreでカタログ全体と開いたオーバーレイを検査します。
既知の例外: 入力欄の枠線(--border-strong)は非テキストコントラスト3:1に届いていません。ラベルと背景で識別できるため現状は許容し、テストの対象外にしています。

開発の流れ

cd apps/web
npm run dev              # /design-system.html で全コンポーネントを操作して確認
npm run test             # ドキュメントの整合・コントラスト・キーボード・axe
npm run build:catalog    # 単一HTMLのカタログを dist-catalog/ に生成(Artifact公開用)

コンポーネントを変更したら同じフォルダの.mdも更新します。props・イベント・スロット・使用トークンの記述が実装とずれると、テストが失敗します。新しいコンポーネントはcomponents/index.tsとREADME.mdへの追加が必要です。
