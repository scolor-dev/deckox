Development

Rust WorkspaceとVueを、同じリポジトリで。

Rust側はCargo Workspace、フロントはViteを利用します。開発時は一時Unixソケットを指定すると、root権限なしでServer–Agent通信を確認できます。

リポジトリ構成

apps/
├── agent/          # Rust / Linux Agent
├── server/         # Rust / Axum Server
└── web/            # Vue + TypeScript
crates/
└── protocol/       # 共有Serialize型
packaging/
├── config/
├── scripts/
└── systemd/
docs/               # このHTMLドキュメント
scripts/
└── package-release.sh

Rustプロセスを起動

最初のターミナルでAgentを起動します。

DECKOX_AGENT_SOCKET=/tmp/deckox-agent.sock \
cargo run --package deckox-agent

開発用パスワードのハッシュを作り、次のターミナルでServerを起動します。Vueの本番ビルドを配信する場合はDECKOX_WEB_DIRを指定します。

printf '%s' '開発用パスワード' \
  | cargo run --quiet --package deckox-server -- hash-password \
  > /tmp/deckox-admin-password.hash
DECKOX_AGENT_SOCKET=/tmp/deckox-agent.sock \
DECKOX_WEB_DIR="$PWD/apps/web/dist" \
DECKOX_ADMIN_PASSWORD_HASH_FILE=/tmp/deckox-admin-password.hash \
cargo run --package deckox-server

Vue開発サーバー

cd apps/web
npm install
npm run dev

Viteはhttp://localhost:5173で起動し、/apiと/healthzをhttp://127.0.0.1:8080へプロキシします。

本番ビルド:

cd apps/web
npm ci
npm run build

環境変数

変数既定値使用プロセス
DECKOX_LISTEN_ADDR127.0.0.1:8080Server
DECKOX_AGENT_CONFIG/etc/deckox/agent.tomlAgent
DECKOX_AGENT_SOCKET/run/deckox/agent.sockServer / Agent
DECKOX_WEB_DIR/usr/local/share/deckox/webServer
DECKOX_ADMIN_PASSWORD_HASH_FILE/var/lib/deckox/admin-password.hashServer
DECKOX_ADMIN_PASSWORD_HASHなしServer（開発・コンテナ向け）
DECKOX_SECURE_COOKIEfalseServer。HTTPS終端時にtrue
RUST_LOG各プロセスのinfoServer / Agent
DECKOX_ADMIN_PASSWORD_HASHでハッシュを直接指定した場合は永続的な保存先がないため、設定画面からのパスワード変更は無効になります。

診断APIのデータ境界

GET /api/v1/diagnosticsは画面表示用のJSON、GET /api/v1/diagnostics/reportは同じ内容のダウンロード応答です。どちらも管理者認証が必要です。

レスポンスはgenerated_at_ms、Serverのversion・status、Agentのconnected・version・error code、公開可能なhost情報、2つのDeckox systemdユニット状態、runtime configの真偽値と件数に固定されています。Agent APIに接続できない場合もHTTPエラーにはせず、Agent由来のまとまりをnullにした部分診断を返します。

診断機能へ項目を追加するときは、生の設定・環境変数・ログ・認証情報を転送せず、共有Protocolへ明示した安全な値だけを追加します。パスワード、ハッシュ、セッション、Cookie、SSH鍵、管理対象ユーザー名、boot IDは追加禁止です。

systemd操作の許可リスト

サービス状態の読み取りは常に可能ですが、起動・停止・再起動・有効化・無効化とjournalログ閲覧は、Agent設定へ完全一致で登録したサービスだけが対象です。

socket = "/run/deckox/agent.sock"

[system]
allow_reboot = false

[services]
allowed = [
  "nginx.service",
  "postgresql.service",
]

[ssh]
managed_user = "operator"

deckox-agent.serviceとdeckox-server.serviceは登録しても起動時に拒否されます。

journalログは最大500行までで、priorityはall・error・warning・infoだけを指定できます。任意のjournalctl引数、ログのダウンロード、Webコンソールは提供しません。

system.allow_rebootは初期値falseです。trueにした場合だけ、パスワード再確認後のホスト再起動を受け付けます。

ssh.managed_userは既存の非rootローカルユーザーだけを指定できます。省略時はSSH公開鍵管理が無効になります。

通常CI

main・developへのpushとPull Requestで、GitHub ActionsのCI Workflowが動作します。

Rust
フォーマット、pedantic・nurseryを含むClippy、ワークスペーステスト、インストール用シェルの構文を確認
Vue
npm ciで依存関係を固定し、ESLint、型チェック、Vitest単体テスト、本番ビルドを実行

Docker Compose

docker compose up --build

ComposeはServer–Agent通信とUIを確認するための開発構成です。http://127.0.0.1:8080/を開き、固定の開発用パスワードdeckoxでログインします。パスワードハッシュを環境変数で渡すため、設定画面からのパスワード変更は利用できません。

制限: コンテナ内のAgentはLinuxホストのsystemdを管理できません。本番のLinux管理用途ではsystemdサービスとして導入します。
